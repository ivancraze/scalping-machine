# Accessibility Pulse Terminal

Проверяй фактический DOM и пользовательский сценарий, а не только JSX. Для audit-only запроса не меняй код без явной просьбы.

## Проверка

- Семантика соответствует назначению элементов; интерактивные элементы доступны с клавиатуры и имеют понятное имя.
- Focus видим, предсказуем и не теряется после открытия меню, смены состояния, ошибки или загрузки.
- Поля, кнопки-иконки, таблицы, списки и сообщения об ошибках имеют необходимые labels, связи и объявления для assistive technologies.
- Цвет не является единственным способом передать состояние; текст и интерактивные элементы сохраняют достаточный контраст во всех состояниях.
- Сортировка, выбор символа, таймфреймы и инструменты рисования имеют доступное состояние и понятную клавиатурную модель.
- Canvas-график сопровождается доступным описанием текущего символа, рынка, таймфрейма и статуса данных. Не объявляй сам canvas полностью доступным без проверяемой альтернативы.

## Результат

Сначала перечисли реальные проблемы по P0/P1/P2. Для каждой укажи файл или элемент, воспроизводимый сценарий, влияние на пользователя и минимальное исправление. Косметические замечания не должны блокировать работу, а ограниченный аудит нельзя называть полной WCAG-сертификацией.

Если пользователь запросил исправления, сохрани визуальное и функциональное поведение за пределами найденных проблем. Выполни относящиеся проверки и `npm run check` при изменении production-кода.
