# Frontend-тестирование Pulse Terminal

Сначала прочитай корневой `AGENTS.md`, проверяемое поведение и существующую тестовую конфигурацию. Выбирай минимальный уровень теста, который подтверждает пользовательский результат или доменный контракт.

## Подход

- Для чистых преобразований market-data используй unit-тесты с граничными значениями, отсутствующими данными и ошибочными ответами внешнего API.
- Компоненты и hooks проверяй через наблюдаемое поведение: ввод, навигацию, загрузку, ошибку, пустое состояние и результат. Не закрепляй внутреннюю структуру компонента без необходимости.
- Сетевые сценарии проверяй на уровне публичной границы с управляемыми ответами. Включай отмену, повторный запрос и отсутствие дублирования, когда это относится к риску задачи.
- Lightweight Charts проверяй через адаптеры и жизненный цикл интеграции. Не делай canvas-снимки основным доказательством корректности бизнес-поведения.
- Исправление бага по возможности сопровождай тестом, который воспроизводит дефект до исправления и проходит после него.

## Отсутствующая инфраструктура

В проекте пока нет тестового runner. Не устанавливай зависимости автоматически. Если запрос явно включает настройку тестов, предложи минимальный стек Vitest + React Testing Library + `@testing-library/user-event` и дождись разрешения на изменение зависимостей. Если инфраструктура не входит в задачу, используй доступные проверки и явно укажи, почему regression-тест не был добавлен.

## Готовность

Запусти только относящиеся тесты во время итераций, затем полный тестовый набор, если он существует. Для изменений production-кода дополнительно запусти `npm run check` и не заявляй об успехе непроведённых проверок.
