# График и realtime-производительность

Прочитай корневой `AGENTS.md`, связанные файлы `widgets/chart` и контракты market-data до изменения. Для review-only запроса также прочитай `.agents/code-review.md` и не меняй код без явного запроса.

## Инварианты

- Создавай chart и series один раз на жизненный цикл контейнера. Не пересоздавай их при обновлении данных или состояния панели.
- Для bulk-истории используй `setData()` только когда заменяется набор данных, сохраняя видимый диапазон пользователя. Для live-свечей используй инкрементальный `series.update()`.
- Каждая подписка, observer и обработчик должны иметь симметричный cleanup. Не допускай повторных WebSocket-подписок или REST-запросов на один поток данных.
- Нативные line-tools должны оставаться привязаны ко времени и цене. При сохранении разметки используй `exportLineTools()` / `importLineTools()` и не затрагивай объекты других графиков.
- Тяжёлые line-tools, вычисления и большие списки оценивай по влиянию на стартовый bundle и main thread. Загружай инструменты лениво, а тяжёлые расчёты выноси из main thread, когда объём данных этого требует.
- Всегда различай Spot и Futures, REST и WebSocket, фактический и ещё не реализованный источник. Не выдавай секундные интервалы или MarketDepth за реальные без соответствующих данных.

## Review и проверка

При ревью сначала перечисляй P0/P1/P2 проблемы: повторные запросы, утечки, блокировку main thread, bundle size, кэширование, подписки и нарушение границ FSD. Для каждой проблемы укажи файл, наблюдаемое влияние и безопасное исправление.

После реализации проверь сохранение масштаба, смену символа и таймфрейма, cleanup после unmount и отсутствие дублирующих запросов. Запусти относящиеся проверки, а для обычного изменения кода — `npm run check`.
